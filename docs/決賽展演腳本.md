# VoiceNursy 決賽展演腳本（3 分鐘）

## 展演前準備

- 後端已啟動：`cd brain && python -m uvicorn api:app --port 8001`
- 前端已啟動：`python -m http.server 3000 --directory safety-ui`
- Ollama 已啟動：`ollama serve`
- 瀏覽器開好 `http://localhost:3000`
- 已預先註冊一個帳號
- 已預先新增 2-3 位病患（其中一位設定 Penicillin 過敏）

---

## 開場（30 秒）

「各位評審好，我們是 OO 團隊，今天要展示的是 VoiceNursy 護理聲助手。

台灣護理師每天花 2 到 3 小時在打病歷，這段時間本來可以用來照顧病人。更危險的是，在大夜班極度疲勞的狀態下，手動輸入很容易出現劑量錯誤。

VoiceNursy 讓護理師用說的就能完成病歷，而且系統會主動攔截危險劑量。我們現在直接 Demo 給各位看。」

---

## Demo 1：登入 + 選病患（20 秒）

1. 輸入帳號密碼 → 登入
2. 「這是我們的巡房模式，上面是我負責的病患。注意王大明旁邊有紅色標籤，顯示他對 Penicillin 過敏，這個資訊等一下會派上用場。」
3. 點選王大明

---

## Demo 2：語音錄音 → SOAP 自動生成（60 秒）

1. 「現在我模擬護理師在床邊口述。」
2. 點麥克風開始錄音
3. 說：「王大明今天傷口發紅，pain scale 4 分，BP 140/90，HR 88，體溫 37.2，PRN 給一顆 Voltaren 25mg」
4. 點麥克風停止
5. 等待 AI 處理（約 10-15 秒）
6. 「各位可以看到，系統自動把我的口述分成了 SOAP 四個欄位：
   - S 主觀：病患傷口不適
   - O 客觀：BP 140/90、HR 88 等數值
   - A 評估：護理判斷
   - P 計畫：給藥紀錄
   
   右邊同時更新了疼痛趨勢圖。」
7. 點確認存檔

---

## Demo 3：防呆警示（40 秒）— 這是得分關鍵

1. 「接下來展示我們最核心的功能：主動防呆警示。」
2. 用手動輸入：「給予普拿疼 5000 毫克」
3. 點生成 SOAP
4. 紅色警示跳出 + 提示音
5. 「系統偵測到 5000mg 超過普拿疼的最大單次劑量 1000mg，立即觸發全螢幕紅色警示。護理師必須明確選擇『確認知悉』或『修改數值』才能繼續，不可能靜默略過。」
6. 點「修改數值」

---

## Demo 4：過敏原攔截（30 秒）

1. 「再展示過敏原交叉檢查。王大明對 Penicillin 過敏。」
2. 手動輸入：「給予 Ampicillin 500mg IV」
3. 點生成 SOAP
4. 紅色警示跳出：「病患對 Penicillin 過敏，Ampicillin 為同類抗生素，有交叉過敏風險！」
5. 「系統不只比對藥名，還知道 Ampicillin 和 Penicillin 是同類抗生素，會自動攔截。這在疲勞的夜班中可以救命。」

---

## Demo 5：交班儀表板（20 秒）

1. 點「交班儀表板」tab
2. 「交班時，接班護理師看到的是這個畫面：每位病患的紀錄摘要、警示次數、疼痛趨勢。不需要讀密密麻麻的文字，幾秒鐘就能掌握全班狀況。」

---

## 技術亮點（20 秒）

1. 點「技術架構」tab
2. 「最後補充一個關鍵：我們所有的 AI 推論都在本機執行，病歷資料完全不出院。這是跟 ChatGPT 最大的差異，也是醫院最在意的資安問題。」

## 評審可能的提問 & 回答

Q：跟直接用 ChatGPT 有什麼不同？
A：ChatGPT 需要把病歷上傳雲端，違反醫療個資法。我們全程本地運行，資料不出院。而且 ChatGPT 沒有劑量防呆和過敏原檢查。

Q：語音辨識準確度如何？
A：我們使用 OpenAI Whisper 模型，並注入 50+ 種醫療術語作為 Prompt，針對台灣醫院的中英台混合語境做了優化。

Q：如何確保 SOAP 分類正確？
A：我們用 Pydantic Schema 強制 LLM 只能輸出 JSON 格式，加上 Prompt Engineering 定義明確的 SOAP 分類規則。護理師在存檔前可以編輯修改。

Q：醫院 WiFi 不穩怎麼辦？
A：我們有 IndexedDB 離線暫存機制，斷網時紀錄存在本地，網路恢復後自動同步。

Q：商業模式是什麼？
A：SaaS 訂閱制，每護理站每月 3,000-5,000 元。也提供地端部署方案給重視資安的醫學中心。

Q：為什麼不用雲端 API？
A：醫療個資法要求病歷資料不能隨意上傳雲端。我們用 Ollama 在本地跑 Llama 3.1，不需要 GPU、不需要網路、不需要 API 金鑰。
