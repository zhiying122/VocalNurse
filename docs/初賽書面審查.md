# VoiceNursy 護理聲助手 — 初賽書面審查資料

## 一、設計理念及主題相符性（30 分）

### 主題對應

本作品選擇「醫療 → 主題二」：以醫療職業環境為主，研發可提升醫病安全及居照護者之產品。

### SDG 對應

- SDG 3 良好健康與福祉：透過主動防呆警示攔截給藥錯誤，直接提升病患安全
- SDG 8 良好工作及經濟成長：解放護理師每日 2-3 小時的文書時間，改善醫療職場環境

### 環保 5R 對應（2R）

- Reduce（減少）：減少紙本病歷列印、減少護理師加班時數
- Rethink（重新思考）：重新思考護理記錄的方式，從「事後打字」轉為「即時語音」

### 設計理念

台灣護理師離職率高達 30%，主因之一是「文書地獄」。護理師每日花費 2-3 小時在護理站輸入病歷，壓縮了實際照護病患的時間。在輪班疲勞下，手動輸入更容易出現劑量錯置、給藥錯誤等醫療疏失。

VoiceNursy 的設計理念是「讓護理師回歸照護本質」。系統定位為隱形的 AI 護理長，在不改變護理師現有巡房習慣的前提下，透過語音輸入自動完成病歷記錄，並主動攔截潛在的醫療疏失。

## 二、創新（獨創）性（20 分）

### 核心創新

1. 中英台混合語音辨識：台灣醫院特有的「中英台夾雜」行話（如「阿公今天 pain scale 4 分，PRN 給一顆 Voren」），現有語音辨識產品無法處理。VoiceNursy 透過醫療術語 Prompt 注入技術，讓 Whisper 模型精準辨識 50+ 種醫療關鍵詞。

2. 主動防呆警示引擎：不只是被動記錄工具，而是主動的醫療安全防線。系統即時比對藥品安全劑量資料庫，偵測到異常劑量（如普拿疼 5000mg）時 2 秒內觸發全螢幕紅色警示。更進一步實作過敏原交叉檢查（如病患對 Penicillin 過敏，系統自動攔截同類的 Ampicillin）。

3. 全程本地運行架構：所有 AI 推論（語音辨識 + SOAP 生成）都在本機執行，病歷資料不出院，從架構層面解決醫療個資法合規問題。這是與 ChatGPT 等雲端方案的根本差異。

4. 一站式語音到病歷：護理師說一句話，系統自動完成「語音辨識 → 藥名標準化 → 個資遮罩 → SOAP 分類 → 防呆檢查 → 視覺化呈現」六步驟，巡房結束紀錄即完成。

### 與現有產品差異

| 比較項目 | ChatGPT | 傳統 HIS | VoiceNursy |
|---------|---------|---------|------------|
| 語音輸入 | 不支援 | 不支援 | 中英台混合 |
| SOAP 自動分類 | 需手動 Prompt | 無 | 全自動 |
| 劑量防呆 | 無 | 部分 | 即時攔截 |
| 過敏原交叉檢查 | 無 | 部分 | 自動偵測 |
| 資料隱私 | 上傳雲端 | 院內 | 本地運行 |
| 離線使用 | 不可 | 可 | 可 |

## 三、實用性（20 分）

### 解決的真實痛點

1. 文書時間：護理師每日減少 2-3 小時打字時間，等同每位護理師每年多出 700+ 小時照護時間
2. 給藥安全：即時攔截劑量異常和過敏藥物，降低醫療疏失風險
3. 交班效率：視覺化儀表板讓接班護理師幾秒內掌握全班狀況，取代 15-30 分鐘的口頭交班

### 使用情境

護理師推著護理車巡房 → 在床邊對平板說話 → 系統自動生成 SOAP 病歷 → 瞄一眼確認 → 存檔。完全不需要改變現有工作流程。

### 技術可行性

- 已完成可運行的 MVP，所有功能真實運作（非模擬）
- 語音辨識：OpenAI Whisper 本地模型
- SOAP 生成：Ollama + Llama 3.1 本地模型
- 不需要 GPU、不需要網路、不需要 API 金鑰

## 四、市場性（20 分）

### 目標市場

- 台灣：493 家醫院、1,600+ 家長照機構
- 護理師人數：約 18 萬人
- 每位護理師每日花 2-3 小時在文書作業

### 商業模式

- SaaS 訂閱制：每護理站每月 NT$3,000-5,000
- 地端部署：醫學中心一次性授權 + 年維護費
- HIS/NIS 介接：客製化串接專案費

### 市場規模估算

- 台灣醫院護理站約 5,000 個
- 滲透率 10% = 500 站 × NT$4,000/月 = NT$2,400 萬/年
- 長照機構另計

### 競爭優勢

- 無痛導入：不改變現有工作流程，學習成本極低
- 安全護城河：防呆警示是說服院方採購的最大誘因
- 個資合規：全程本地運行，醫學中心最在意的資安問題直接解決
